# Android Chrome 실기기 점검 절차 (2026-10-20) — 아직 **한 번도 실기기로 돌리지 않음**

지금까지의 모바일 수치는 전부 에뮬레이션(Playwright Pixel 5, 360/390/430px, CPU·네트워크 조절)이다. 아래는 목사님(또는 신학생 1명)이 실제 Android 휴대전화의 Chrome 에서 20~30분에 할 수 있는 점검표. 결과는 `docs/REPORT_android_<날짜>.md` 에 그대로 적는다(통과/실패/메모). **실기기 결과가 없으면 "실기기 통과"라고 쓰지 않는다.**

**기록 보존 우선**: 1번(캐시 삭제)처럼 저장소를 비우는 시험은 **시크릿 창 또는 시험용 브라우저(다른 Chrome 프로필)** 에서 한다. 평소 쓰는 Chrome 에서 하려면 먼저 기록 탭 → JSON 백업을 내려받는다.

준비: Android 휴대전화 + Chrome 최신 · 주소 https://aqedah.github.io/MILALWV/ · 모바일 데이터(Wi-Fi 아님)로 한 번, Wi-Fi 로 한 번 · 기기 정보(모델·Android·Chrome 판) 적기.

| # | 항목 | 하는 법 | 재는 것 / 보는 것 | 결과 |
|---|---|---|---|---|
| 1 | 최초 로딩 | Chrome 설정 → 인터넷 사용 기록 삭제(캐시 포함) 뒤 주소 열기 | 창세기 1장 본문이 보일 때까지 초(손목시계로 됨). 모바일 데이터에서 5초 안이면 양호 | |

실패하면: 화면을 캡처하고 번호·기기·Chrome 판과 함께 적어 주면 에뮬레이션으로 재현해 고친다.

# 5단계 기능 우선순위 제안

기준: "실제로 본문을 연구하는 데 어떤 문제가 풀리는가" + 이미 확보된 실제 V1 자료의 학문적 의미를 훼손하지 않을 것.

| 순위 | 후보 | 왜 이 순위인가 | 전제 |
|---|---|---|---|
| 1 | **반복·인용·재진술 비교기** | 신학생 과제(창 22 반복어, 욥 32–37 재진술)에 바로 쓰이고, 지금 '반복' 도구·검색식 보관의 연장이라 자료 추가 없이 됨. 관찰 메모와 바로 연결 | 없음 |
| 2 | **PDF 내보내기** | 과제·논문 제출용. Markdown 은 이미 되므로 "원문(RTL)·표시·관찰/해석 표"를 한 장으로 — 브라우저 인쇄 CSS 로 먼저(설치 없음), 그 다음 파일 생성 | 실기기 점검 7·10 통과 뒤 |
| 3 | **구조 분석 연습 기능** | 수업용: 학생이 먼저 모절을 그려 보고 MILAL 판정·BHSA 원자료와 비교. **학생 답을 MILAL 판정과 섞지 않도록** 기록 종류(`kind:"practice"`)를 따로 둬야 함 | IF-1 확정·첫 승인 뒤(비교 대상이 '승인 전'이면 혼란) |
| 4 | **오프라인 캐시(Service Worker)** | 교회·강의실 Wi-Fi 가 약할 때. 자료가 책별로 쪼개져 있어 캐시 설계는 쉬우나, 캐시가 낡은 분석 파일을 붙들면 승인 상태 표시가 어긋날 수 있어 STUDY_V 연동이 먼저 | 실기기 1·2 측정 뒤 |
| 5 | **태블릿 최적화** | 두 단(본문 | 구조/상세) 배치. 효용은 크지만 사용자가 적고, 지금 화면이 768px 에서도 깨지지 않음 | 실제 태블릿 사용자 생기면 |

이 순서는 제안이고, 연구자가 바꿀 수 있다. HSA3 별도 시각화(`docs/HSA3_DISPLAY_DESIGN.md`)는 연구자 답을 받은 뒤 1~2 사이에 끼워 넣는 것을 권한다.
