## 0. 지시를 먼저 코드와 대조한 결과

지시 7이 지적한 네 가지는 모두 실제로 맞았습니다. ① `qRangeOf()`가 `S.wide`를 빼먹어 '구약 전체'로 찾은 식을 보관하면 책 범위로 재실행됨 ② `qWhyHTML()`이 처음 5,000개 묶음만 살펴 뒤쪽 절의 근거가 빠짐 ③ 근거 설명에 `lex=HNH` 같은 코드가 그대로 노출 ④ `qkey`가 남아 보관함의 다른 식을 실행해도 예전 예시의 단계 카드가 남음. 모두 고쳤습니다. 범위는 지시대로 두고, 새 화면 구조를 만들지는 않았습니다(아래 §7 참고).

## 1. 검색 범위와 보관함 재현성 (A)

- 보관 기록에 **실제 실행 범위**를 적습니다: `all`(구약 전체) / `book`(현재 책 전체) / `chapter`(장·장 범위) + 책·장 번호 + 판 표시 `v:2`. 다시 열면 **범위까지 그대로 복원**(`qApplyRange`), 예시 안내(`qkey`)는 해제.
- 옛 기록(판 표시 없음)은 그대로 읽히되 목록에 "옛 기록(범위 표기 전)"이라 적고 책·장 범위로 실행합니다(그때 전체 검색이었는지는 알 수 없음 — 정직하게 표시).
- 재현성 시험: 구약 전체로 예시1(227건) → 보관 → 출 3장으로 이동 → 보관함에서 실행 → 구약 전체·227건·같은 첫 절들 → 한 번 더 실행해도 동일.
- **첫 화면에 찾는 범위**("찾는 범위 — 창세기 1장" / "구약 전체")와 전환 단추를 두어, 어느 범위로 예시를 돌리는지 모른 채 실행하는 일이 없게 했습니다. '지금 조건' 상자에도 범위와 전환 단추가 있습니다.

## 2. 결과 근거의 정확성 (B)

- 실행 때 결과 전체(상한 20,000 묶음)를 훑어 **절마다 맞은 묶음 수와 대표 묶음 ≤3개**를 보존합니다(`qWhyIndex`). 저장하던 5,000개 묶음 복사본은 없앴습니다.
- 시험: `w1:phrase function=Subj / w2:word / w1 < w2`(구약 전체, 상한 도달 20,000건, 3,291절) — 모든 결과 절에 근거가 있고 마지막 절(민 29:1)도 근거 3개. 첫·중간·마지막 절의 묶음 수가 `qRun`을 다시 돌려 직접 센 값과 일치.
- 표시 구별: "이 절에서 맞은 묶음 **n**개 가운데 3개를 보입니다" + 상한에 걸렸으면 "(상한 20,000건 안에서 센 것 — 실제는 더 있을 수 있음)", 계산 중단이면 "(계산이 중단되어 실제는 더 있을 수 있음)". 확인하지 않은 값을 정확한 건수처럼 쓰지 않습니다.

## 3. '맞은 자리'(이전 이름 '왜 맞았나')를 쉬운 말로 (C)

조건 → 실제로 맞은 원문 → 본문에서 살펴볼 것 순서입니다. 예: "명사문인 절(클로즈) → וְהִנֵּה דְבַר־יְהוָה אֵלָיו / 주어인 구 → דְבַר־יְהוָה / 사전형 '여호와'인 낱말 → יְהוָה". 관계 기호는 "앞의 표현보다 뒤에 나타남"(`<`), "바로 뒤에 나타남"(`<:`) 등으로, 이름 관계는 "w1 가 w2 보다 뒤에 나타남"으로 풉니다. 설명 문구는 기존 `qSay`(조건을 그대로 읽는 함수)에서 만들어 자료가 판정한 범위를 넘지 않습니다. 코드(`typ=NmCl`, 노드 번호 `clause#…`, 검색식 원문)는 **"자료 코드로 보기"** 펼침 안에 남겼습니다.

## 4. 예시 안내 불일치 방지 (D)

- 단계 카드: 지금 실행된 식의 정규형이 그 예시의 단계 중 하나와 같을 때만 표시. 예시 설명·예시용 '이렇게 연구해 보세요'는 식이 예시 원본과 같을 때만(`qExampleLive`), 아니면 실제 조건(문장 종류·역할·낱말 등)을 읽은 일반 안내.
- 보관함 실행과 검색 메모 복원은 `qkey`를 지웁니다.
- 범위만 바꿔도 "⚠ 검색 범위(창세기 22장 → 구약 전체)가 변경되었습니다 … 다시 찾기"(조건과 범위가 함께 바뀌면 둘 다 적음).

## 5. 검색 메모의 연구 흐름 (E)

- 검색 메모 `anchor.query`에 검색식·실행 범위(`rg`: 종류+책·장)·결과 상태(`full`/`limit`/`steps`)·건수·절 수·BHSA 판·정규형을 보존합니다. 관찰·해석은 기존 메모 칸 그대로(검색식은 메타데이터, 판정이 아님).
- 기록 탭에서 검색 메모를 누르면 검색 화면으로 가서 **같은 식·같은 범위로 다시 실행**하고 "기록 당시: 창세기 22장 · 5건 · 전체 계산 · BHSA 2021 → 지금: …" 한 줄로 견줍니다. 같으면 "같은 결과입니다", 다르면 경고색으로 "결과가 다릅니다 — 자료 판이나 범위·조건이 달라졌는지 확인하세요"(시험: 건수·판을 바꿔 둔 메모로 경고 확인). 옛 메모(범위 종류 없음)는 범위 이름과 메모의 닻으로 복원.
- 절·구간 메모와 비교 메모의 동작은 그대로입니다.

## 6. 비교기 잔여 점검 (F)

- 원문 연속 표현이 **절 경계를 넘으면** "절 경계를 넘음"이라 표시하고 절 제목에 개수를 적습니다(창 22 사례 1개: 22:1→2 אַבְרָהָם וַיֹּאמֶר הִנֵּנִי וַיֹּאמֶר). Python 기대값에도 `cross`를 넣어 대조.
- 기능어 제외 어순 대응은 A·B의 **원문 구간을 그대로 보이되 건너뛴 낱말을 흐리게**(Markdown은 ⟨ ⟩, 인쇄도 흐리게). 본문 전체를 흐리게 하면 여러 대응이 겹쳐 혼란스러워 항목 안에서 보였습니다.
- 설명 문구를 "같은 말이 이어진다는 관찰일 뿐, 인용·재진술 판정이 아님"으로 두었습니다. 기존 정확성 검사(독립 계산 대조 24+F 4)는 그대로 통과.

## 7. 지시와 다르게 하거나 하지 않은 것

- "검색 범위를 첫 화면에서 변경": 장 선택은 위의 장 이름(기존 장 선택기)을, 전체/이 범위 전환은 새 단추를 씁니다 — 별도 범위 선택기를 또 만들지 않았습니다.
- "건너뛴 낱말을 A/B 원문에서 흐리게": 본문 전체가 아니라 해당 대응 항목 안의 원문 구간에서 흐리게 했습니다(이유 위).
- 검색 메모를 열 때 '이 검색 다시 실행' 단추를 따로 두지 않고 **누르면 바로 재실행**합니다(탭 하나 절약, 결과 비교 줄이 그 역할).
