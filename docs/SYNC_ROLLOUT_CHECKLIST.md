## 1. 켜기 전 점검표 (순서대로, 하나라도 빠지면 켜지 않음)
- [ ] `firestore.rules` 전문을 읽고 승인 (특히: 주석 `rev` 정확히 +1, `server_at`=서버 시각, 묘비 되살리기 금지, 진짜 삭제 금지, 나눔 `hidden==false` 조회만 공개)
- [ ] 콘솔에서 **지금 운영 규칙을 복사해 보관**(되돌리기용), 그 다음 `firestore.rules`를 붙여 넣고 게시
- [ ] 게시 직후 앱(배포본)에서: 비로그인 나눔 보기 됨 / 로그인 뒤 낱말 메모 동기화 그대로 됨 / 나눔 올리기 됨 / 남의 글 내리기 안 됨
- [ ] **기록 백업**: 시험에 쓸 기기마다 기록 탭 → 'JSON 백업 내려받기' (복구 지점)
- [ ] `config.js`에 `window.ANNOT_SYNC_ENABLED=true;` 추가 → 커밋·배포 (스위치는 코드 한 줄이라 되돌리기 쉬움)
- [ ] 기기 1에서 로그인 → 기록 탭 상단 "동기화: 맞춤" 확인 → 메모 하나 쓰기 → Firestore 콘솔 `users/{uid}/annots/{id}`에 `rev:1`, `server_at` 보임
- [ ] 기기 2에서 로그인 → 그 메모가 보임(내려받기) → 고치기 → 기기 1에 반영(rev 2)
- [ ] 두 기기에서 같은 메모의 **같은 칸**을 동시에 고침 → 한쪽에 "겹친 수정 1건" 알림, 메모 안에 ⟪충돌 사본⟫으로 양쪽 글 모두 있음
- [ ] 기기 1에서 지움 → 기기 2에서 사라짐(목록) · 콘솔에는 `deleted:true` 묘비 남음
- [ ] 비행기 모드에서 메모 쓰고 → 다시 연결 → 올라감("올릴 것 n건" → "맞춤")
- [ ] 모두 통과하면 HANDOFF 2절·이 문서 상태를 "운영 켬(날짜)"으로 고침

## 2. 문제가 생겼을 때 (되돌리기)
1. `config.js`의 `ANNOT_SYNC_ENABLED` 줄을 지우거나 `false` → 배포. 기기 기록은 그대로 남는다(동기화만 멈춤).
2. 규칙까지 되돌려야 하면 0단계에서 보관한 운영 규칙을 다시 붙여 넣는다.
3. 기록이 이상해졌으면: 기록 탭 → '복원'으로 1단계에서 내려받은 백업을 넣는다. 복원은 기존 것을 지우지 않고(더 새 판만 바꿈, 충돌은 사본으로) 들어간다. 복원 전에 '지금 상태 먼저 백업'을 누른다.

## 3. 백업·복원 절차 (일상)
- 백업: 기록 탭 → 'JSON 백업 내려받기' → `milal-백업-YYYY-MM-DD.json`. 논문·과제 마감 전, 기기 바꾸기 전, 동기화 켜기 전에.
- 복원: 기록 탭 → '복원' → 파일 고르기 → **미리 보기**(새로 들어올 것·고쳐질 것·건너뛸 것·충돌 사본 수) → '복원하기'. 자세한 규칙은 `docs/NOTES_STORAGE_DESIGN.md` §5.
- Markdown·CSV는 읽기용이지 복원용이 아니다.

## 4. 아직 안 된 것 / 한계
- 앱 연결부(`firebase.js`)는 실제 서버에서 아직 돌려 보지 못했다(이 작업 환경에서 Firebase CDN에 닿지 않음). 알맹이는 에뮬레이터로 검증했고, 연결부는 30줄 정도라 1단계 점검표의 실제 시험이 곧 검증이다.
- 묘비 정리(1년 뒤 일괄)는 설계만. 기록이 수천 건이 되기 전엔 문제 없음.
- 낱말 메모(옛 저장)는 목록 통째 동기화 그대로(규칙에 500개·칸 고정만 추가).
