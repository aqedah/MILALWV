## 3. Firestore 동기화 — 에뮬레이터 결과와 운영 배포 준비 (작업 C)

- 알맹이 `app/sync_core.js`(순수 함수, 브라우저·node 공용): 기기 기록에 `srv_rev`·`dirty`·`base` 를 두고 **세 갈래 병합**. 관찰·해석은 문장을 조각내지 않음 — 한쪽만 고쳤으면 그쪽, 둘 다 고쳤으면 서버 글을 두고 기기 글 전체를 `⟪충돌 사본 · 기기 · 시각⟫` 아래 덧붙임. 태그는 합집합. 지움은 OR(되살리지 않음). 서버 내용과 같으면 쓰지 않고 채택(응답 유실 뒤 재전송 = 멱등).
- 앱 연결 `firebase.js`: 저장할 때마다 1.5초 모아 트랜잭션으로 올림, 모음 `onSnapshot` 으로 내려받음(고치는 중인 기록은 보류 → 다음 올리기에서 병합), 실패 건 15초 뒤 재시도, 충돌이 있으면 알림. **스위치 `ANNOT_SYNC_ENABLED` 기본 꺼짐.** 낱말 메모(옛 방식) 동기화는 그대로.
- 에뮬레이터 시험 19건(규칙 적용, 기기 A·B·C 흉내 — `pipeline/firestore_rules_test/sync.test.mjs`): 만들기/내려받기/고치기, 다른 칸 동시 수정(충돌 없이 합침), 같은 칸 충돌(양쪽 보존), 오프라인 삭제 vs 수정(묘비 이김), 되살리기 시도 차단, 낡은 기기 재업로드(덮어쓰지 못함), 응답 유실 뒤 중복 전송(멱등), 일부 실패·재시도, 저장 중 끊김, 서버 없는 묘비 안 올림, 보류 뒤 병합, 표시 칸, 서버 문서에 기기 전용 칸 없음, 낱말 메모 유지, 태그 합집합 — 모두 통과.
- 운영 전환 점검표·되돌리기·백업/복원 절차: **`docs/SYNC_ROLLOUT_CHECKLIST.md`**. 한계: 앱 연결부는 이 환경에서 Firebase CDN 에 닿지 않아 실서버에서 아직 못 돌려 봄(문법 검사만). 규칙 게시 뒤 점검표 1단계가 그 시험입니다.
