## 1. 검색 결과 동일성 판정 — 결과 지문

지적이 맞았습니다. 건수·상태·판·범위 이름이 같다는 것은 **일치한 본문이 같다는 증거가 아닙니다**. 고친 것:

- **지문(`qFingerprint`)**: 실행 결과의 묶음마다 `단위 + 첫 낱말의 BHSA 낱말 번호 + 낱말 수`를 적고(예: `clause12345+7 phrase12346+2 word12347+1`), 전체를 정렬한 뒤 해시(FNV 계열 두 개)합니다. 내부 색인이 아니라 **BHSA 낱말 번호**를 쓰므로 자료를 다시 만들어도 같은 BHSA 판이면 같은 지문입니다. (구·절의 BHSA 노드 번호는 앱 자료에 없어 낱말 번호로 식별했습니다 — 같은 단위·같은 시작 낱말·같은 길이면 같은 객체입니다.)
- **검색 메모에 보존**: 검색식 원문·정규형(`canon`)·정확한 범위(`rg`: all/book/chapter + 책·장)·BHSA 판·상태(전체/상한/중단)·건수·절 수·**지문(`fp`, `fpv:1`)**. 기존 메모는 손대지 않았고(지문 없는 채로 읽힘), 삭제도 없습니다.
- **재실행 판정(`qSameVerdict`) 다섯 가지**:

| 경우 | 화면 문구 |
|---|---|
| 전체 계산 + 지문 일치 | "전체 검색을 마쳤고 결과 지문이 같습니다 — 동일한 검색 결과로 확인." |
| 지문 불일치(건수 같음) | "건수는 같지만 결과 지문이 다릅니다 — 일치한 본문이 달라졌습니다." (경고색) |
| 지문 불일치(건수 다름) | "결과 지문이 다릅니다 — 검색 결과가 달라졌습니다." (+ 자료 판/조건 다름 표시) |
| 상한·중단이 있음 | "상한·중단이 있어 확인된 범위까지만 비교 — 그 안에서는 지문이 같습니다/다릅니다." |
| 옛 기록(지문 없음) | "동일성 확인 불가 — 옛 기록이라 결과 지문이 없습니다(건수 같음/다름). 이번 실행으로 메모를 다시 저장하면 다음부터 확인할 수 있습니다." |

- 시험: **합성 사례** — 건수·판·범위·조건이 모두 같고 지문만 다른 메모를 만들어 재실행 → "건수는 같지만 … 달라졌습니다"로 검출(같다고 표시하지 않음, 화면에서도 확인) · 지문 없는 옛 기록 → "확인 불가" · **실제 BHSA 검색**(창 22 관계식 103건, 구약 전체 '보라' 369건) 재실행 → 지문 일치 "동일한 검색 결과로 확인" · 상한(20,000)에 걸린 검색의 메모 → 상태 limit 과 지문 저장, 판정 "확인된 범위까지만 비교".

## 2. 검색 범위 명칭

대조 결과: 실제 검색 대상은 `stSpans()`가 정합니다(구약 전체 스위치가 켜지면 전체, 아니면 책 `R.b`의 `R.c1`~`R.c2`장). 그런데 저장값은 옛 상태값 `S.range`(기본 "book")에서 가져와, **창 22장만 검색하면서 보관함에 "창 22 (책 전체)"라 적는** 오류가 있었습니다. 고친 것:

- `qRangeOf()`는 `stSpans()`에서 만듭니다: 전체 → `all`, 그 책의 1장~끝장 → `book`, 그 밖 → `chapter`(판 표시 `v:3`).
- 이름(`qRangeLabel`): "구약 전체" / "창세기 전체 (1–50장)" / "창 22장" · "창 22–24장". 오늘 낮에 저장된 `v:2` 기록(range 가 "book"이라도 실제는 장 범위)은 **장 범위만** 적고 '책 전체'라 하지 않습니다. 옛 기록은 "옛 기록(범위 표기 전)" 표시 유지.
- `qApplyRange()`: `book`은 그 책 1장~끝장, `chapter`는 저장된 장, `all`은 전체 스위치. 시험 R1~R5: 저장값·화면 이름·실제 대상(`stSpans`)이 세 경우 모두 일치, 낮 기록은 "창 22"로 보이고 실제로 창 22만 검색(49건).
