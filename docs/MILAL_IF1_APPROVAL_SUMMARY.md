# MILALWV-IF-1 최종 승인 요약 (연구자용, 2026-10-20) — 상태: **DRAFT**

읽는 데 5분이면 됩니다. 기술 세부는 별첨(`docs/MILAL_IF1_APPROVAL_PROPOSAL.md` 2판, `docs/MILAL_INTERFACE_DRAFT.md`, `docs/REPORT_real_v1_2026-10-20.md`, `docs/REPORT_bhsa_native_compare_2026-10-20.md`)에 있습니다.

## 1. 무엇을 승인하자는 것인가

MILAL(분석 도구)이 낸 욥기 관계망(V1)을 MILALWV(보기 앱)로 넘기는 **파일의 구조와 변환 규칙**을 정식 규격으로 삼자는 것입니다.
승인해도 **MILAL의 어떤 관계도 학문적으로 승인되는 것이 아닙니다.** 관계의 승인은 별도 파일(`approvals.json`)에, 연구자가 규칙·범위 단위로 따로 적습니다(지금 0건).

## 3. 파일의 구조 (일곱 칸)

| 칸 | 담는 것 | 누가 정한 값인가 |
|---|---|---|
| source | 어떤 MILAL 판(커밋·규칙판)·어떤 입력(해시)·BHSA 판으로 만들었는가 | 기록(MILAL 출력 그대로) |
| nodes | 절(BHSA clause) — 장·절·본문·낱말 번호·절 원자 번호 | BHSA |
| groups | V1 의 묶음(발언 단위·보고 도입/내용·큰 발언 가설 …) | MILAL |
| relations | MILAL 판정 관계 — 종류(종속·틀–내용·병행·닫음·소속), 상태, 모절→자절 방향, 규칙, 근거 | MILAL (`family` 칸만 변환기가 보기용으로 붙인 분류) |
| native_relations | BHSA 원본의 mother/rela — MILAL 판정과 **분리** | BHSA |
| evidence | 규칙 검사 결과(통과/미결/연구자) — 검사 항목별로 따로 | MILAL (P2 기록) |
| issues | 경쟁 후보·미결·미배정·직접 관계 없음(연구자 기각 기록이 있을 때만) | MILAL |

**판정 상태의 뜻**(V1 그대로): 확정=연구자 채택 · 잠정=규칙 통과, 연구자 미확인 · 경쟁=후보 여럿 · 미배정=묶이지 않음. 앱은 확정만 '확정 사슬'에 넣습니다.
**없는 값**: 칸이 없거나 비어 있으면 "모름"입니다. 변환기는 값을 지어 채우지 않습니다. "관계 없음(모름)"과 "없다고 판정함"(기각 기록)은 다른 칸입니다.

## 4. 앞으로 MILAL 결과가 바뀌면

1. 호환되는 **선택 칸 추가** → 같은 규격 안의 개정(앱은 모르는 칸을 무시).
2. **필수 칸 추가·기존 칸의 뜻 변경** → 새 판(IF-2) 검토.
3. **MILAL 규칙·판정이 바뀐 새 결과** → 같은 규격으로 **새 파일**, 출처·해시 다시 기록.
4. 연구자 승인 기록은 **해시가 달라진 결과에 자동으로 옮겨 가지 않음**(다시 검토).

## 5. 승인하더라도 남는 제한

- V1 은 절마다 BHSA 원본 관계를 1건만 담아, 한 절에 절 원자가 둘 이상인 39절의 둘째 원자 mother 는 이 파일에 없고 **원자료 사본(`bhsa_native_job.json`)에만** 있습니다. 앱은 사본으로 보여 주되 관계로 만들지 않습니다.
- `family` 는 변환기의 보기용 분류이지 MILAL 판정이 아닙니다.
- 규칙 검사 '실패'는 반례가 아닙니다(반례는 따로 표시할 때만).
- **HSA3(이음매·구성 판정)는 이 규격의 범위 밖**입니다 — 별도 규격 시제품(읽기 전용)으로 다룹니다.
- 규격 승인 ≠ 관계 승인.
