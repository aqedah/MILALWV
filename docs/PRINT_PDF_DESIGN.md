# PDF 내보내기 사전 설계·시제품 결과 (작업 F, 2026-10-20)

## 방식
별도 렌더링 엔진 없이 **브라우저 인쇄 + 전용 CSS**(`app/print.js`, `study.css` 의 `@media print`). 기록 탭과 비교 화면에 '인쇄·PDF' 단추 → 화면 위에 인쇄용 문서(`#printRoot`) → `window.print()` → Chrome 에서 '대상: PDF로 저장'. 모바일 Chrome 도 같은 경로로 PDF 를 만든다.

## 담는 것
제목·범위 · 히브리어 원문(RTL, `direction:rtl; unicode-bidi:isolate`) · 사용자 표시(형광펜·밑줄·⟦ ⟧) · **관찰 / 해석** 구분(색·이름표) · 비교 결과 표(동일 어휘·형태·양쪽에 다 있는 형태·공통 연쇄·한쪽에만 있는 어휘) · MILAL 참조(메모에 붙은 것, 시험 자료는 '시험 자료 — 실제 판정 아님') · 자료 출처·판(BHSA 2021, 번역, STUDY_V, 인쇄일). 사용자 해석과 MILAL 판정은 다른 칸.

## 검증(에뮬레이션, Playwright A4 PDF)
| 시험 | 결과 |
|---|---|
| 기록 인쇄(창 22:2 형광펜·괄호·절 메모) | RTL 유지, 형광펜 5·괄호 2·관찰 1·해석 1·출처, PDF 1쪽 185KB |
| 비교 인쇄(창 22:1–10 ↔ 11–19) | 두 단, 동일 어휘 표 25행, 실선 86·점선 30, 연쇄 10, 메모 1, PDF 4쪽 410KB |
| 긴 비교(욥 32–37 ↔ 38–42) | PDF 24쪽 726KB, 0.4초 |
| 인쇄 매체 | 앱 화면·하단 메뉴·인쇄 단추 숨김, 문서만 |
| 절 잘림 | 절 블록(`.prv`)·메모·표 행에 `break-inside:avoid` — 절 가운데서 쪽이 나뉘지 않음(비교 2쪽 PNG 로 확인) |
실기기(Android Chrome 인쇄 → PDF)는 아직 안 함.

## 한계와 다음 결정
- 글꼴: 기기에 히브리어 글꼴(Noto Serif Hebrew)이 없으면 시스템 대체 글꼴로 찍힘. PDF 에 글꼴을 심으려면 파일 생성 방식(jsPDF 등)이 필요하나, 그 경우 RTL·히브리어 모음 배치가 라이브러리 품질에 걸린다.
- 두 단 비교는 A4 세로에서 읽을 만하지만 긴 절이 많으면 '위아래로' 한 단이 낫다(인쇄 옵션으로 추가 가능).
- 제안: 당분간 **브라우저 인쇄 방식으로 운영**하고, 실기기 점검(Android Chrome)에서 글꼴·쪽 나눔이 문제없으면 정식 기능으로 둔다. 파일 생성 엔진은 수요(이메일 첨부 자동화 등)가 생길 때 다시 본다.
